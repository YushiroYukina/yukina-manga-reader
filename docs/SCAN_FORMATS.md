# v1.1 扫图格式支持（2026-10-16）

本次在 Windows、Android 和 Mac 源码中新增：ZIP／CBZ、RAR／CBR、7z／CB7，以及 JPG／JPEG、PNG、WebP、BMP、GIF（静态首帧）。原有 PDF、EPUB、MOBI 保留。

## 导入和阅读

- 压缩包作为一本书，递归识别包内图片，按路径与文件名自然排序（2 在 10 前），忽略隐藏文件及 __MACOSX。
- 使用“导入文件夹”导入散图：同一目录中的图片合为一本书；子目录可作为各卷。混合目录中的文档和压缩包仍各自作为一卷。选择“每个文件独立”时，图片文件夹仍保持一本书，避免每张图变成独立图书。
- 单独通过文件选择器选中的图片各自作为单页图书；多页散图请导入它们所在的文件夹。
- 批量导入、第一页缩略图、合辑总封面、阅读进度、时长和阅读状态沿用现有功能。
- 原文件保持只读。只保存路径／授权 URI、书库记录与封面缩略图；不整包解压、不写页面磁盘缓存。Windows 的封面缓存仍遵循原来的非 C 盘规则，安卓直接使用 SAF 授权读取内部存储和 TF 卡。

## 当前边界

不支持加密／带密码、缺卷的分卷压缩包、压缩包内嵌套压缩包、动图播放。单页压缩前图片文件上限 32 MiB，单本上限 20000 页。固实 RAR／7z 可能需要从前面的数据开始解码，跳页或生成封面会比 ZIP 慢；不会为提速将整本书解压到磁盘。

## 构建

桌面：先安装各平台现有依赖；运行 `python tools/prepare_archives.py`（Mac 位于 reader/tools），从官方源下载并核验固定版本的 7-Zip。PyInstaller 打包脚本缺少组件时也会自动准备。成品自带解码组件，阅读时无需安装 7-Zip 或联网。

安卓：`tools/build.py` 自动调用 `tools/prepare_archives.py`，从 Maven Central 下载 SHA-256 固定的 libarchive-android 1.1.6 AAR，编入 Java 绑定及四种 ABI 的原生库。签名沿用本机原有开发密钥。源码不包含密钥、SDK 或下载的解码器二进制。

## 验证情况

Windows：50 项自动化检查通过，包括 ZIP／RAR／7z／散图读取、自然排序、原文件哈希不变、无解压文件落地，以及原阅读和书库回归检查。额外验证了 Windows 成品内置解码器、五种来源的封面生成和 RAR 图形界面打开。

Android：37 项核心检查与 67 项真机检查通过，正式应用已更新为 0.2.1-alpha。真实 TF 卡上一册 176 页 ZIP 的封面、阅读、拖动翻页、随机页解码及源文件哈希验证通过。详细范围见 ANDROID_DEVICE_SCANS_2026-10-16.md。

Mac：维护者返回源码在 M1 / macOS 26.5.1 完成 56 项 Cocoa 原生回归，包含全部新增格式与中文目录、混合路径前缀。未在维护者机器重新构建独立 .app；本次 v1.1 独立应用由 GitHub Apple Silicon 环境构建并另做打包组件检查。详见 MAC_FIX_VALIDATION_2026-10-16.md。
